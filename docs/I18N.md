# Multi-language — what is translated, and what is not

Built 2026-08-15. Seven languages: **English · हिन्दी · ಕನ್ನಡ · മലയാളം · मराठी · தமிழ் · తెలుగు**.

This is the "phase 2" of CLAUDE.md's multi-language plan, scoped to UI chrome and the
three legal documents. It is deliberately **not** a full-app translation — see
[What is NOT translated](#what-is-not-translated), which is the important half of this
document.

---

## Where things live

| Path | What |
|---|---|
| `web/src/lib/i18n/locales.ts` | The locale list, native names, `resolveLocale`, storage key |
| `web/src/lib/i18n/messages/{en,hi,te,ta,kn,ml,mr}.ts` | UI strings. `en.ts` exports the `Messages` type — **the other six are typed against it**, so a new key is a compile error until all seven carry it |
| `web/src/lib/i18n/index.ts` | `getMessages(locale)` |
| `web/src/lib/i18n/legal/types.ts` | The `LegalDoc` shape (sections / bullets / `**bold**`) |
| `web/src/lib/i18n/legal/{en,hi,…}.ts` | Privacy · Terms · Disclaimer, as data |
| `web/src/context/language-context.tsx` | `useLanguage() → { locale, setLocale, t }` |
| `web/src/components/legal/legal-document.tsx` | The one renderer for all 3 documents × 7 languages |
| `web/src/app/(dashboard)/settings/language/language-picker.tsx` | The picker |

**Adding a string:** add the key to `messages/en.ts` → TypeScript fails the other six →
fill them in. That failure is the feature; a missing translation should never reach the
person who cannot read the fallback.

**Adding a language:** add to `LOCALES` + `LOCALE_META` + `LOCALE_ORDER` in `locales.ts`,
add `messages/<code>.ts` and `legal/<code>.ts`, register both in the two `index.ts` maps,
and add the tag to the pre-paint script's array in `app/layout.tsx`. If it is a new
*script* (not just a new language), it also needs a font — see below.

## Decisions worth not re-litigating

### No next-intl, despite CLAUDE.md naming it
CLAUDE.md's phase-2 note says "via next-intl". This does not use it, on purpose:

- next-intl's routing mode wants a `[locale]` path segment, which would restructure all
  39 routes for a feature whose scope is UI labels and three documents.
- Its no-routing mode is a provider wrapped around a flat dictionary — which is exactly
  what `theme-context`, `density-context` and `ui-mode-context` already are in this repo.
  Three working precedents beat a new dependency.
- `messages/` is laid out the way next-intl expects, so adopting it later is a config
  change, not a rewrite.

Flagged here rather than done silently.

### The choice is stored in localStorage, not on the profile
Same as `theme`. A `profiles.language` column is the right follow-up — the view-lock
reasoning in CLAUDE.md (survive a reinstall, for the person least able to re-find the
setting) applies equally — but it needs a hand-applied migration, so it is listed under
[Open](#open) rather than half-built. `LanguageProvider` will not need changing: it just
gains a server-supplied initial value.

### Every language is written in its own script
`LOCALE_META.nativeName` is the label; `englishName` is the muted second line. A list
reading "Hindi / Telugu / Tamil" in Latin is unusable by exactly the person who came to
this screen because the app is in a language they cannot read. The English name stays for
the caregiver setting up somebody else's phone.

### Legal documents are data, and English governs
The three pages were hand-written JSX. Seven languages would have meant 21 copies of that
markup which must agree about structure forever. They are now one renderer + seven content
files.

**Every non-English rendering states that the English version is the one that applies**
(`legal.translationNotice`), shown *before* the text, plus a "Read in English" toggle. That
toggle is local state — it switches the document only, never the app language, because
someone checking a translation against the original should not have to put their whole
phone into English and then navigate back through settings they can no longer read.

### Fonts: five Noto families, and they cost English users nothing
Inter contains **zero** Devanagari, Telugu, Tamil, Kannada or Malayalam codepoints. Without
webfonts those six languages fall through to whatever the OS calls `sans-serif` — usually
fine on Android and Windows, tofu boxes wherever it is not.

`app/layout.tsx` loads `Noto_Sans_{Devanagari,Telugu,Tamil,Kannada,Malayalam}` with
`preload: false`, each subset to its own script, and `globals.css` appends them as
`--font-indic-tail` to **both** the sans and mono stacks. Font fallback is resolved per
glyph, so Latin still renders in Inter and only Indic glyphs come from Noto.

- The **mono** chain needs the tail too — `.navigation-label`, badges and metrics are mono,
  and JetBrains Mono has no Indic coverage either.
- `--font-indic-tail` is a variable rather than a repeated list because it must appear in
  four places (two theme tokens + the `body`, heading and `.font-mono` rules that reference
  the raw next/font variables). A tail on only some of them renders Telugu correctly in a
  heading and as tofu in the nav label underneath it.
- Five families cover six languages: Hindi and Marathi share Devanagari.

Verified 2026-08-15 in-browser: on a Telugu page only `Noto Sans Telugu` reported `loaded`
— Devanagari, Tamil, Kannada and Malayalam all stayed `unloaded`. An English page fetches
none of them.

## What is NOT translated

Stated plainly because a language picker implies more than it delivers, and the picker
itself says so on screen (`language.scopeNote`, `language.alarmNote`).

- ~~**The native alarm screen.**~~ **DONE 2026-08-16** (`2f51851`) — see the note at the
  end of this file. Was: Kotlin, `values/strings.xml`, English only. This was the gap
  that matters most — it is the screen the least technical user meets at 3am — and closing
  it is **not** just a `values-hi/` drop: Android resource qualifiers follow the *device*
  locale, not the in-app choice, so the selected language must cross the bridge
  (a `language` field on `syncSchedule`, documented in BRIDGE_CONTRACT.md) or the two
  silently disagree. See CLAUDE.md → Post-M2 §2.
- Medication names, dosages and notes — **user data, never translated**. A medicine is
  called what the person typed.
- The medication wizard, care circle, health vault, notifications, onboarding, the guided
  tour, Remi's copy, and all auth screens.
  - **The guided tour specifically** (`components/guide/guide-content.ts`): 21 steps of
    literal English. No file under `components/guide/` imports `useLanguage`, so this is
    structural, not a missing key — re-confirmed 2026-08-21 when an adversarial pass went
    looking for Telugu tour strings to stress-test and found there are none.
    **Reviewed and left as-is**, for two reasons worth recording so it is not re-opened as
    a quick win: machine-translating 126 strings of product guidance is not acceptable on
    a medical-adjacent surface without native review, and the harm is already reduced —
    **`/settings/setup-guide` IS translated in all seven languages** (`guideMedsTitle`,
    `guideInviteTitle`, `guideCaregiverTitle`, `guideSkipTitle` and their bodies) and
    covers the same onboarding ground. The tour is optional, dismissible, and not a safety
    surface; the translated path exists beside it.
- The Telegram bot and every server-sent message.
- Page `<title>` / meta descriptions — these are read by crawlers and by people arriving
  from the Play listing, neither of which has seen a `localStorage` value the server cannot
  read.

## Mascot alt text — added 2026-08-20

`mascot.{welcome,happy,proud,peaceful,curious}` carries Remi's accessible names in
all seven locales. Short, and deliberately **not** naming the character differently
per language — "Remi" is a name, so only what he is *doing* is translated.

These are announced only where a placement passes `altKey`; most placements are
decorative and render `aria-hidden`, because a mascot that repeats the heading
beside it is noise in a screen reader.

Like the rest of the non-English strings these are machine-produced and are part
of the outstanding native-speaker review below.
